# Бэкенд Al-Farabi Global Symposium 2026

Django + Django REST Framework. Отдаёт сайт (одностраничный фронт) и API для:
- регистрации и входа участников,
- заявок на участие (форма «Регистрация» на странице «Участникам»),
- подачи статей в сборник и журналы (сумма взноса показывается для сведения, оплаты на сайте нет),
- админки оргкомитета с выгрузкой в Excel.

## Быстрый старт (разработка)

Всё ставится в виртуальное окружение `backend/.venv` — глобальный Python не трогаем.

```bash
cd backend
python -m venv .venv                      # один раз
.venv\Scripts\activate                    # Windows (PowerShell: .venv\Scripts\Activate.ps1)
python -m pip install -r requirements.txt
python frontend/build_site.py             # собрать сайт из "../al-farabi-symposium-2026 V2.html"
python manage.py migrate
python manage.py createsuperuser          # вход в админку по email
python manage.py runserver 127.0.0.1:8001 # порт 8000 занят другим проектом
```

Без активации можно вызывать напрямую: `.venv\Scripts\python manage.py runserver 127.0.0.1:8001`.
VS Code берёт это окружение автоматически (`.vscode/settings.json`).

- Сайт: http://127.0.0.1:8001/
- Админка: http://127.0.0.1:8001/admin/
- Письма: пока в `.env` нет пароля SMTP — печатаются в консоль; с паролем — уходят по-настоящему.
- Тесты: `python manage.py test tests`

## Как подключён фронт

`frontend/build_site.py` копирует исходный HTML в `frontend/site/index.html` и:
- встраивает в `submitReg()` отправку заявки на `POST /api/registrations/`;
- чинит форму: выбранные «День участия» / «Формат участия» заливаются золотым
  (раньше в тёмной теме выбор был почти не виден), а при ошибке подсвечиваются
  и перечисляются конкретные незаполненные поля;
- над формой показывает срок приёма, «приём закрыт» (вместо формы) и данные вошедшего участника;
- добавляет **личный кабинет** (`frontend/cabinet.js` + `cabinet.css`): ссылка «Sign in / Account» в шапке,
  `#/cabinet` — вход, регистрация, восстановление пароля, вкладки «Заявка», «Статьи» (подача, доработка,
  отзыв, скачивание, сумма взноса), «Профиль»; `#/reset-password` — новый пароль
  по ссылке из письма. Все тексты на ru / kk / en;
- на странице Publications берёт суммы взносов из админки и добавляет кнопку «Подать статью»;
- страницы Speakers и Programme — из админки, PDF — из «Документов для скачивания»; язык по умолчанию — английский;
  значок вкладки — логотип КазНУ;
- «Открыть на карте» у мест проведения открывает в новой вкладке страницу `/map/?v=0|1&lang=` (`templates/venue_map.html`,
  Leaflet + OpenStreetMap): площадка, отели, где поесть, остановки рядом (переключаются, список с расстояниями), ссылки для маршрута в Google Maps, 2ГИС, Яндекс Картах. Список мест —
  `frontend/nearby.json`; обновить: `python frontend/fetch_nearby.py`, затем `python frontend/build_site.py`;
- шапка: «Вход / Кабинет» в строке меню (на телефоне — в «Меню»), слова с дефисом («аль-Фараби») не переносятся
  по дефису, казахские пункты меню компактнее, чтобы помещаться в одну строку.

Исходный файл не меняется. **После каждой правки фронта (и `cabinet.js`/`cabinet.css`) запускайте скрипт заново.**
Сайт нужно открывать через сервер (`python manage.py runserver 127.0.0.1:8001`), а не двойным кликом по файлу —
иначе форма и кабинет не смогут обратиться к серверу.

API отвечает на языке, переданном сайтом в `Accept-Language` (`config/middleware.py`, тексты — `config/i18n.py`);
админка всегда на русском.

Если фронт размещён на другом домене — задайте перед основным скриптом
`<script>window.AFGS_API = 'https://api.example.kz'</script>` и
`CORS_ALLOWED_ORIGINS` в `.env`.

Все запросы от вошедшего пользователя передают заголовок
`Authorization: Token <token>` (фронт берёт токен из `localStorage['afgs-token']`).

## API

### Аккаунт — `/api/auth/`
| Метод | Путь | Что делает |
|---|---|---|
| POST | `register/` | `{email, password, full_name, organization?, country?, phone?, lang?}` → `{token, user}`; отправляет письмо подтверждения |
| POST | `login/` | `{email, password}` → `{token, user}` |
| POST | `logout/` | удаляет токен |
| GET / PATCH | `me/` | профиль (email менять нельзя) |
| POST | `password/change/` | `{old_password, new_password}` → новый токен |
| POST | `password/reset/` | `{email}` → письмо со ссылкой `FRONTEND_URL/#/reset-password?uid=…&token=…` |
| POST | `password/reset/confirm/` | `{uid, token, new_password}` → `{token, user}` |
| POST | `email/verify/` | `{uid, token}` |
| GET | `email/verify/link/?uid&token` | ссылка из письма, возвращает на `FRONTEND_URL/#/?email_verified=1` |
| POST | `email/resend/` | повторное письмо подтверждения |

### Заявки на участие — `/api/registrations/`
| Метод | Путь | Что делает |
|---|---|---|
| POST | `` | подать заявку, **вход не нужен**. Поля как в форме фронта: `name, org, country, email, phone, day (6/7/both), role (listener/speaker), direction, topic, note, lang` |
| GET | `` | мои заявки (по аккаунту и по подтверждённому email) |
| GET / PATCH | `<id>/` | посмотреть / изменить свою заявку |
| POST | `<id>/cancel/` | отменить |

Одна активная заявка на email. Участнику и оргкомитету уходят письма.
Заявки, поданные без аккаунта, автоматически привязываются к аккаунту после подтверждения почты.

### Статьи — `/api/papers/` (нужен вход и подтверждённая почта)
| Метод | Путь | Что делает |
|---|---|---|
| GET | `` | мои статьи |
| POST | `` | multipart: `title, authors, abstract, keywords?, direction?, language, target, file` |
| GET / PATCH | `<id>/` | правка — только в статусах «Подана» и «Нужна доработка» |
| POST | `<id>/withdraw/` | отозвать |
| GET | `<id>/file/` | скачать рукопись (автор или сотрудник) |

`target`: `proceedings` (сборник, бесплатно), `tuva` (300 USD), `vestnik_philosophy`, `vestnik_religion`,
`vestnik_pedagogy`, `vestnik_psychology` (60 000 ₸). Суммы — в `PUBLICATION_FEES` в `config/settings.py`.
Файлы: doc, docx, pdf, rtf, odt до 20 МБ.

### Оплаты на сайте нет

Путь участника заканчивается отправкой статьи: она попадает в админку (**Статьи**), там редакция её
рассматривает. Сумма взноса видна автору для сведения; реквизиты оргкомитет присылает сам
(в письме «Статья принята» об этом сказано). Приложение `payments` (модель и старые записи) оставлено
в коде, но API, раздел админки и вкладка кабинета отключены.

### Справочники — `GET /api/meta/`
Дни, форматы участия, издания со взносами.

## Что включается в админке

**Настройки → Настройки симпозиума** (одна страница):
- приём заявок и приём статей — открыт или закрыт, срок «до (включительно)» с автоматическим закрытием на следующий
  день, своё сообщение о закрытии на русском, казахском и английском (пусто — стандартное, с датой окончания);
- требовать ли подтверждённую почту для подачи статей;
- почта оргкомитета для уведомлений (несколько адресов через запятую), отправлять ли письма участникам;

**Статьи → Публикационные взносы**: сумма и валюта по каждому изданию, приём статей в издание вкл/выкл.

Значения из `.env` используются только как начальные при первом запуске.

## Докладчики

Страница «Докладчики» на сайте берёт данные из админки: **Докладчики → Докладчики / Группы докладчиков**.

- Карточка: ФИО, страна/город, должность, тема, сессия, день — на русском, казахском и английском
  (пустой перевод заменяется русским), фото (без фото — инициалы), порядок, «Показывать на сайте».
- Пустая тема → «Тема доклада уточняется».
- Группы — это вкладки-фильтры на странице: название, подзаголовок, порядок, видимость.
- Человек в двух группах (например, докладчик и модератор) — две карточки; кнопка «Сохранить как новый» помогает.
- Все 39 карточек, которые были на сайте, загружены при `migrate` из программы фронта (`speakers/seed_speakers.json`).
- Если сервер недоступен, страница показывает встроенные данные, как раньше.
- **Из заявки:** при подтверждении заявки докладчика создаётся скрытый черновик карточки в группе
  «Черновики из заявок»; оргкомитет переносит его в группу и включает показ. Для заявок, подтверждённых раньше, —
  действие «Создать черновик карточки докладчика для сайта». Отклонение или отмена заявки скрывает карточку.

## Программа и документы

Страница Programme берёт расписание из админки (`/api/program/`, приложение `program`): **Программа: дни → пункты →
группы («Модератор», «Докладчики») → строки**. Строка либо ссылается на карточку докладчика (тогда данные берутся из
карточки, а строка видна только когда карточка опубликована), либо содержит свои ФИО/должность/тему/текст.
Вся программа из фронта перенесена при `migrate` (`program/seed_program.json`, 4 дня, 36 пунктов, 62 строки;
39 строк связаны с карточками). В карточке докладчика есть блок «Выступления в программе».

PDF «Скачать программу» и «Скачать информационное письмо» — **Документы для скачивания** (по языку; нет файла на
языке — русский; нет никакого — встроенный во фронт).

## Докладчик на сайте — только после одобрения

Никто не попадает на сайт и в программу автоматически: показ включает оргкомитет («Показывать на сайте» в карточке).

## Роли сотрудников

Создаются автоматически при `migrate`. Выдать роль: **Пользователи → сотрудник → отметить
«Статус персонала» → выбрать группу**.

| Роль | Что может |
|---|---|
| Оргкомитет | заявки: просмотр, подтверждение/отклонение с письмом, выгрузка в Excel; докладчики на сайте |
| Редакция | статьи: скачивание рукописей, статус и комментарий автору, выгрузка |
| Администратор симпозиума | всё выше + настройки симпозиума, суммы взносов, сотрудники и их роли |

Ограничения: выгрузка в Excel — отдельное право для каждого раздела. Администратор симпозиума не может сделать
кого-то суперпользователем, выдать права в обход ролей или изменить суперпользователя.
Права ролей можно менять в **Группах**; вернуть исходные — `python manage.py setup_roles --reset`.

## Админка оргкомитета

- **Заявки на участие**: фильтры по дню, формату, стране, направлению; действия «Подтвердить»,
  «В лист ожидания», «Отклонить» (участнику уходит письмо на его языке), выгрузка в CSV для Excel.
- **Статьи**: скачивание рукописи, смена статуса с письмом автору (при «Принята» — с суммой взноса).

## Продакшен

1. Скопировать `.env.example` в `.env`, заполнить (секретный ключ, домен, SMTP).
2. PostgreSQL: `pip install "psycopg[binary]"`, `DB_ENGINE=postgres`.
3. `python manage.py migrate && python manage.py collectstatic`
4. Запуск: `gunicorn config.wsgi` за nginx (HTTPS). Папку `media/` **не** раздавать через nginx —
   файлы статей отдаются только через API с проверкой прав.
